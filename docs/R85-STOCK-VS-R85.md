# Kitchen 0.2.35 基础实现 vs R85：直接同场实测

日期：2026-09-29。交叉测试已完成。

比较保持 Larry v4 INT8 ConvRot、Euler/beta 8 次实际前向、CFG 1、同一 INT8 视频 VAE 和 GPU FP32 音频 VAE。基础臂不导入任何自定义 DiT 补丁，走上游原生 attention 和 FP32 CPU 视频输出；R85 启用冻结的全部 DiT 精确优化、RGB8 融合及 pinned D2H。两臂使用同一 CPU x264/AAC/MP4 编码器。

Case 1 在 GPU 0 按 ABBA、Case 8 在 GPU 3 按 BAAB 测试。每个位置独立进程，1 次预热和 1 次正式。每 case 每臂共 2 次正式。Case 8 第一个 B 使用旧审计程序，其 R85 计算与后续相同；因基础臂计数接口不匹配产生的失败/中止任务全部排除，原始记录保留。

**计时从冻结 condition 到 MP4 落盘**，包括 DiT、模型迁移、双 VAE、输出交接与 CPU 成片；不含初始化读权重、Qwen/参考图处理、HTTP/排队/上传。哈希在全部成片完成后验证，未混入正式时间。

## 具体优化范围

两臂已经共同保留：LoRA 预合并、INT8 ConvRot 权重、旧 encoder 的相同冻结 condition、上游 INT8 视频 VAE 内的 RMS/激活/Linear 融合、DynamicVRAM/权重预取和相同 CPU 编码器。它们不构成本次新增收益。

R85 相对 stock 新增：AttentionTensorContainer 交接和去 clone、直接 BSHD 输出、V 量化、Norm/调制/残差到 INT8 输入融合、跨 block FC2 消费、5090 D v2 dense 主循环调度与 Q 缓存、INT8 GEMM raster 配置、out-proj/FC2 gate epilogue、QKV/RMS/RoPE/量化融合、K-only anchor、末层无用行计算消除；视频输出启用 finalize/RGB8 融合和双 pinned buffer 异步 D2H。当前没有跨 step 近似 cache 或稀疏跳算。

这场实验直接验证上述整组改动的累计收益，没有逐个开关重跑消融，因此不能给每个融合分配一个独立百分比。单请求组也没有下一请求可重叠，CPU export 跨请求重叠的吞吐收益没有包含在本次结果中。

## 质量与口径

已接受的 8 个正式请求全部通过视频 latent、音频 latent、RGB8、PCM 四 SHA 对同一历史黄金输出验证；同 case 两臂逐位相同。两臂各 8 NFE / 400 次 dense。这里两边已经用 INT8 VAE，**没有计入 TRT→INT8 的约 40% 解码阶段收益**。

固定 R85 是本次优化臂：动态 VAE，旧参考 encoder；静态 VAE＋R234/R244 尚未并入，因此不能把后续 VAE 阶段百分比追加到本数字。

这是两个代表性约 10 秒片段的交叉小样本，不是五个 30 秒故事全量重跑。单请求延迟的倒数仅能作串行容量折算，本轮没有测多请求 CPU/GPU 重叠的稳态吞吐。
