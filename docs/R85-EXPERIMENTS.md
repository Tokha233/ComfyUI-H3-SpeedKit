### DPCache #1557 已经真正测试过

移植的是上游 DP 选步和二阶 Taylor hidden 外推，在“计算步”完整跑50层，“预测步”外推最后hidden后仍执行当前final layer/sampler；不是KV cache，也不是有精确校验器的推测解码。

为避免多份FP32 hidden占显存，factor放CPU，分2048行传输；计算和搬运开销计入DiT。每个新任务若先完整采样校准一次再生成，不能忽略校准成本。Larry K7/K6完整计算步已做同卡ABBA：

| 方案 | 完整请求 A→B / s | 降时 | 5代表片段SSIM | LPIPS | 32k音频 |
|---|---:|---:|---:|---:|---:|
| Larry对照 | — | — | .715888 | .317968 | .709905 |
| DPCache K7 | 247.859→230.437 | 7.03% | .708504 | .335680 | .661782 |
| DPCache K6 | 249.578→200.878 | 19.51% | .712565 | .335519 | .656803 |

LPIPS五例均退化；K6音频五例均下降。无LoRA16只做case1预算筛选，K10更接近参考但更慢；K8完整263.14s、32k音频.466790，未胜过Larry。来源S37。

## 3. FP8、BF16 attention 和 NVFP4

| 方向 | 结果 | 为什么没采用 |
|---|---|---|
| FP8权重＋Kitchen dense，9/12 | 5故事FP8 821.4s/故事 vs INT8 786.7，LPIPS .286572 vs .280303 | 没有比INT8更快/更好 |
| FlashInfer #5493 FP8 QKV大融合 | 5代表片段20正式；完整均值222.172→225.000s，慢1.273% | 上游相对分散FP8的3.35×不能套到优化INT8；新QKV误差更大 |
| #5472 SM120 BF16 dense | 5代表片段；均值质量略升，DiT约翻倍 | 局部误差小，但不是速度升级，且有单例退化 |
| DiT局部NVFP4 | 5代表片段；case1同卡完整−4.73% | 32k均值.709905→.533766，更多step未恢复速度质量双赢 |
| FP8/NVFP4 attention新核 | R157/R160/R173，真实长QKV、oracle | 部分阈值/FP4局部快，但误差显著上升；未完成此新attention的业务成片，不借旧NVFP4媒体代表 |
| NVFP4 VAE decoder | R326系列，真实原FP16源量化，2case | 速度更慢，RGB质量下降；不采用 |

#5493 实际从原BF16＋同一Larry合并后量化FP8，没把INT8再转FP8；其余Linear保留INT8，attention也仍INT8。真实长QKV链43.725952→48.403696ms，慢10.698%；五片段SSIM .715888→.711492，LPIPS .317968→.333412，32k音频 .709905→.649937。其接入与R85不同，不能说是R85原样替换实验。来源S38。

NVFP4 VAE的同一FP16 decoder参考、原始RGB SSIM如下；它与成片对BF16/50的SSIM不是一个指标。

| case | 当前INT8 s / SSIM | NVFP4 FFN s / SSIM | NVFP4 all s / SSIM |
|---|---|---|---|
| 1 | 9.305763 / .999213 | 9.782639 / .981177 | 9.520128 / .974303 |
| 8 | 9.825153 / .999219 | 10.36823 / .985150 | 10.07533 / .979089 |

NVFP4 all视频阶段allocated峰值约少25%，不代表完整请求峰值少25%，也没有证明增加并发后净吞吐更高。来源S25。

## 4. DiT INT8 主循环和 epilogue 的负结果

| 家族 | 典型实验 | 最深结论 |
|---|---|---|
| 更大/更小tile、pipeline、寄存器限制 | R08/R14/R30/R32/R34/R35等 | FC1 config3/swizzle8、QKV config5保留；其他多数局部增益未传递到完整周期 |
| CUTLASS4.5→4.8、cuBLASLt | 同源同调度比较；真实长FC1 | 换版本本身无稳定收益；不能用不同调度归因版本 |
| 无饱和MMA、直接store、warp shuffle epilogue | R20/R51/R52等 | 精确但多持平/更慢 |
| FC1＋SwiGLU/ConvRot大融合 | R23、R65、R162–171等 | 长90461行无稳定正收益；完整H256融合255regs并有spill，约慢15–16.5% |
| 利用原权重天然2:4/S4/E4M3可表示性 | R40/R50等 | 完整可用tile为0；没有靠元素比例获得精确稀疏/低比特GEMM |
| producer warp/寄存器重排、ping-pong | R119/R124/R131/R132/R134–152 | 资源受限、spill或barrier成本；多个变体0/30胜，未采用 |
| max3、行内/跨行softmax/pack重排 | R115–125/R155/R158/R179–180 | 输出可一致但无速度收益；有的最终SASS相同 |
| 精确exp2查表 | R122 | constant/shared大幅更慢，停止扩大 |
| 复用scratch、紧凑V | R113/R114 | 完整case1/8收益不一致或慢，不采用 |
| query-window→outproj双缓冲/高优先级 | R181–185 | 780组配对；普通32K双缓冲仍慢约.455–.483%；没有完整业务新收益 |
| 新Kitchen N8 PV思路移植 | R186–189 | 384边界、320长配对精确，慢约.20–.33%；3个源配置编译出同一SASS |

R126以前“112性能候选”包含变体/复测，不是112种独立新算法；R171/R178/R185等审计归档不作为新加速轮次。曾出现设备/工具停滞的组合，保留“未完成该项验收”，不自动算sanitizer通过。来源S15、S17、S27。

## 5. VAE FC1/FC2 主循环、融合与graph

| 实验组 | 实际范围 | 正式结果/决策 |
|---|---|---|
| R193–200输出锁页、static、tile8/16 | decode＋部分完整DiT | static有小收益；tile8/16更慢3.76%/6.20%，拒绝 |
| R203–229 RoPE、量化、双stream、FC2、direct epilogue | 全15latent及多轮局部/2case | static＋R207保留；双stream/FC2更慢，V quant整体持平 |
| R233–253 FC1大融合、RoPE/Q、cached-Q | 多种核与60正式decode | R234v2/R244保留；FC1大融合慢25–32%；临时buffer复用慢.221% |
| R257–274 TMA/tile/EVT/StreamK/store/固定shape | 7类74配置148shape，64正式decode | StreamK反序一张卡+.10–.14%，另一张−.46–.67%；不固化 |
| R277–294 2CTA/flatten/更多epilogue | 9方向、48正式decode | 未达到95%理论利用率，无可靠新赢家 |
| R295–313向量quant/FFN分块/C++批量提交 | 1530记录3060poison、48正式decode | micro最好+6.41%；真实FFN分块慢1.8–2.5%，拒绝 |
| R314–323完整FFN graph/权重轮换/精简建图 | 真实decode，反序复核 | 建图181–185ms→5–6ms，整行仍慢.4–.6%，分块慢3–4%，拒绝 |

热micro重复相同权重/张量，真实VAE切换36层权重并穿插attention、quant和输出。减少scratch或launch数量不自动转化为整段加速。R266初筛“8–10%”曾被公平graph回放推翻，缩为约.6%，再经真实decode否决；开源描述不应保留最乐观初筛数字。来源S20–S25。

## 6. CPU、导出和新运行库

| 方向 | 证据 | 决策 |
|---|---|---|
| CPU FP32音频VAE，4线程 | 3保存latent，4.49–9.44s，PCM不等于GPU；GPU约.12s | 不迁移；未获得CPU/GPU并行服务收益 |
| CPU视频封装常驻/缓冲直传 | R159，3段每段14次含预热导出 | 原export已有serve模式；新from_numpy_buffer收益方向不一致，不重计常驻收益 |
| Torch2.14/Triton3.8完整R85 | 4预热＋8正式生成，2case | DiT持平，输出变化且质量升降混合；保留旧栈 |
| 新ptxas13.4编译同源dense | 固定capture筛选 | 比旧编译约慢.53–.54%，未采用 |

所有负结果只限制本次实现、shape、权重、配方和硬件。它们可为后续开发节省重复试错，但不证明该技术在其他模型和GPU上无用。
