# 原生高精度 VAE 基础版 → 全部 R85 优化：直接实测

新同场实测：**Kitchen 0.2.35 基础 Larry v4 8 步＋原生 FP16 视频 VAE → 固定 R85＋INT8 视频 VAE，两个代表片段的总生成耗时减少 11.591%，串行容量折算增加 13.111%**。每请求平均节省 30.66 秒。完整计时从冻结 condition 到本地 MP4，排除 Qwen/参考处理、HTTP/排队/上传与首次读权重。

历史“BF16 满血版”实际为 BF16 DiT/Qwen＋FP16 视频 VAE＋FP32 音频 VAE。本次读取 safetensors 头和运行 dtype，视频原权重 562 个张量均为 FP16，运行也是 torch.float16。因此主速度基线准确标为“原生 FP16 视频 VAE”；单独 BF16 VAE 尚未测试。

## 1. 两端配置与计时范围

| 项目 | A：基础版 | B：当前优化版 |
|---|---|---|
| DiT 与 LoRA | 相同 Larry v4 baked INT8 ConvRot | 相同权重 SHA |
| 采样 | Euler/beta，8 次实际前向，CFG1，shift12/4 | 完全相同 |
| DiT 实现 | Kitchen 0.2.35 stock，不导入项目 DiT 补丁 | 冻结 R85 累积精确优化 |
| 视频 VAE | 原生非量化 FP16；原 FP32 CPU 输出 | INT8 ConvRot；最终 RGB8 融合、双 pinned D2H |
| 音频 VAE | GPU FP32 | 同一 GPU FP32，PCM 完全一致 |
| 输入与输出 | 冻结相同 condition，旧 encoder 结果；同 CPU x264/AAC/MP4 | 相同 |
| 不计入 | Qwen/参考处理、HTTP/队列/上传、首次读权重 | 同左；也不含静态 VAE/R234/R244 候选 |

每个片段两臂都在同一张物理卡上测试。Case1 先 A 后 B，Case8 先 B 后 A；每臂独立 Python 进程、1 次预热＋2 次正式，共 4 预热＋8 正式。这个实验的顺序是 AB/BA，不能与之前 r368 的 ABBA/BAAB 混称。模型身份和实际库路径在启动/结束审计；哈希不混入计时。

两边 VAE 使用同一份 .35 配套上游模型源码（SHA aae581a7…7225f）。源码按 QKV 权重类型分派：原生 FP16 权重走 optimized_attention；INT8 权重走 Kitchen INT8 attention。本次比较的是“固定 .35 实现上的原生 FP16 与 INT8 decoder”；最早版本的整个 VAE 软件栈未在本轮恢复。

| 1 | 10.125 s | 270.678977 | 240.114236 | 11.292% | 30.565 |

同等工作量的各片段均值之和 **529.002116 → 467.684957 GPU 秒**。这是各卡内配对后的相同工作量合计，不是两卡并行墙钟。计算：降时=1−B/A；容量折算=A/B−1。

## 4. 对照质量

相同 latent 的全部 15 片段，INT8 VAE 对原生 FP16：成片 SSIM 均值 **0.989070**，LPIPS **0.007589**，原始 RGB8 PSNR 均值 **58.67 dB**；音频 PCM **15/15 逐字节一致**。这支持“当前测试中的画面差异很小、音频不变”，不等于逐像素无损，也不是多 seed 人工盲评结论。

完整生成 A/B 的 video/audio latent、PCM 都与历史黄金相同；A 的 RGB 与本臂预热重复相同，B 的 RGB 仍与 R85 历史黄金相同。两个臂的视频 RGB 由于 VAE 改变而不同。所有 15 个同 latent 解码的 B 也恢复历史 RGB/PCM，Case1/8 解码测评与本次完整生成 RGB SHA 对应。

后续 R85 精确算子与“视频 VAE 量化”分开验收：前者保留固定 INT8 的四 SHA；后者用同 latent 像素/感知指标描述微小变化。新主表没有使用历史 TRT→INT8 的质量数字。

## 5. 与之前 6.685% 的区别

之前 r368 的两端**都使用 INT8 VAE**，测得总降时 6.685%、串行容量 +7.164%，回答固定 INT8 VAE 后纯算子与输出工程的累计收益。本次 A 换回原生 FP16 VAE，因此把 VAE 量化替换一起计入。两场都有各自直接计时，不能相加，也不能把差额归为一项精确消融。

LoRA 预合并、DynamicVRAM、原分配器和 CPU 编码器已是两端的共同基础。本次未测连续请求队列的 CPU/GPU 重叠收益，容量百分比不等于实测稳态吞吐。全 15 的新增完整 DiT/服务对照、更多 seed 与长队列仍可扩测。
