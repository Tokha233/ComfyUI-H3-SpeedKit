30 项优化，逐项决定怎样公开

涵盖 DiT 融合、VAE、异步输出、服务调度与未采用实验。展开查看机制、精度边界、实际证据和移植要求。

01Larry v4 固定 LoRA 预合并配方/转换工具 · 历史状态：共同基础＋

怎么做：捕获实际 post-cast 生效的权重，按原旋转空间、alpha 和 scale 规则固化为 baked INT8 ConvRot checkpoint。两臂都直接加载它。

为何有收益：固定 adapter 不再反复计算或保存临时更新张量；模型身份也更容易复现。

精度边界：不得把 LoRA 矩阵直接加到 INT8 字节；不得重复挂 Larry；旧 Turbo 的 alpha/16 规则不能套用。冻结 SHA 为 9eccf52e…71fec12。

历史证据：当前基础版已 baked，这一项没有计入本次 A→B 的新增收益。

怎样开源：先发身份与方法；合法源码闭包和 post-cast 等价验证后再发转换器；不分发私有 baked 权重

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

02原生分配器与 DynamicVRAM 权重预取沿用上游 · 历史状态：共同基础＋

怎么做：保留 native allocator（--disable-cuda-malloc）与原 DynamicVRAM；使用 pinned 主机权重和预取流，让下一层搬运与当前层计算重叠。

为何有收益：隐藏权重搬运，控制 24 GB 显存中的组件切换。

精度边界：event、源 tensor 与目标 owner 必须活到消费结束；不能把 allocator 的 max_split_size_mb:512 当成 DynamicVRAM 开关。

历史证据：约 97.01% 是该次 H2D 重叠比例；基础版已有此能力，不能再算一遍 R85 新增收益。

怎样开源：不独立重写 DynamicVRAM；说明配置与复现条件，不算自有新增

归属：上游已有能力，项目沿用。本仓库尚未迁入对应 GPU 实现。

03QKV 载体、所有权转移与去 V clone首版 DiT/runtime · 历史状态：R85 固定＋

怎么做：使用 AttentionTensorContainer 显式交接量化载体；消费完成后提前释放原引用，去掉已证明不必保留的 V clone。

为何有收益：减少显存带宽、复制和 Python 载体处理；降低同时存活的大张量数量。

精度边界：只删不再使用的副本；量化 code/scale、layout 和 stream 消费顺序保持。未知 owner/stride 回退。

历史证据：组合减少 0.908%，包含调制，未单独拆出 container 或 clone 的完整请求收益。

怎样开源：提取 carrier/owner，未知 stride、consumer 回退

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

04RMSNorm 与 video/audio/text 分段调制融合首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：同一 kernel 完成归一化、对应区段调制和输出，减少中间张量；对合法 stride 单独分派。

为何有收益：少一次或多次全量 BF16 写读，以及小 kernel launch。

精度边界：RMS reduction、epsilon、广播、token 边界和两次 BF16 舍入照旧，不能因融合而用更高精度贯穿。

历史证据：迁移消融累计到本层 29.459518 s，相对 stock 累计 −2.643%；不是这一项独享 2.643%。

怎样开源：RMS/分段调制；明确 token 区间和 BF16 落点

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

05Residual、gate、norm2 与调制融合首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：在合法消费链中合并 residual 与后续 norm2/调制；保留真实浮点落点。

为何有收益：减少 residual 张量读写和 launch；缩短 block 内的串行依赖链。

精度边界：gate 的 BF16 乘法与 residual 的 FP32 FMA/最终 BF16 必须按原顺序；strided 输入不得冒充 contiguous。

历史证据：相对 stock 的组合累计 −2.826%，未把相邻消融差异当成独立服务收益。

怎样开源：Residual/norm 融合；回归 FMA、strided 与 boundary

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

06Norm/Residual/调制直接产生 ConvRot INT8 输入首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：限定业务 shape、stride 和 act 下，Norm/调制或 Residual/Norm/调制直接接 ConvRot、scale 与 INT8 code 生成。

为何有收益：省掉 GEMM 输入前的一次大张量往返。

精度边界：保留 group、旋转顺序、scale、padding、随机量化开关与原 BF16 中间落点；不满足资格时转回上游。

历史证据：单纯打开开关不代表加速。该项在最终整组对照中验证，没有独立完整请求百分比。

怎样开源：直接产生 ConvRot code/scale；契约与回退先行

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

07K5376/K7168 ConvRot 寄存器与线程调度首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：按 5376/7168 宽度调整 register、shuffle 与线程组织；9/19 迁移配置分别为 768/640 线程。

为何有收益：减少 shared-memory 往返和不合适的线程工作划分。

精度边界：每个宽度独立资格；不得覆盖新版未知 act_weight/act_eps 语义。K14336 SwiGLU 更大融合不在默认路径。

历史证据：迁移组合累计到寄存器 ConvRot 为 29.386356 s；不宣传单独 −2.885%。

怎样开源：K5376/K7168 分派；不是所有宽度通用调度

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

08Attention 直接输出 BSHD 与精确 V 量化首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：attention 直接写 BSHD，使用保留原 scale/padding 的 V 量化路径，减少 transpose/copy。

为何有收益：以消费者布局产生结果，避免全量激活搬运。

精度边界：V 的行/组 scale、量化饱和和 padding 与基线相同；仅改地址映射不能改有效元素顺序。

历史证据：对应相对 stock 累计 −1.340% / −2.099%；这些是有继承关系的组合。

怎样开源：BSHD 与 V quant 精确交接；比较新版是否已覆盖

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

09SM120 dense：3 槽 TMA、Q 寄存器缓存、提前释放 K首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：D128、Q128/K128；3 槽 TMA ring；8 compute warp 加 4 producer warp；240/24 寄存器额度；Q 放寄存器，K 消费后提前交还槽位。

为何有收益：隐藏 K/V 搬运，减少 Q 的重复读取，使整数 MMA 更连续。使用 SM120 能力，不套用 SM100 的 TMEM/tcgen05。

精度边界：66,560 B shared；原 KV 遍历、online softmax、概率 U8/PV S8 量化与累加次序保留；dense 不删 attention block。

历史证据：纳入整组 R85 对照；历史后续 dense 小改完整周期仅 −0.1245%。不能把 pure-MMA 95.3% 比值写成整机理论利用率。

怎样开源：SM120 dense；先与 Kitchen .36 比较，只保留净增量

归属：基于 SageAttention/Kitchen 的硬件适配。本仓库尚未迁入对应 GPU 实现。

10o_scale 等于 1 的恒等乘法消除首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：只对精确等于 1 的分支省略恒等乘法；其他 scale 仍用原实现。

为何有收益：减少主循环末端依赖和指令。

精度边界：不是把相近 scale 当作 1；KV 顺序、softmax 和输出舍入保留。

历史证据：组合串行容量 +0.450%；没有把恒等乘法单独拆成这一收益。

怎样开源：精确等于 1 的 scale 分支；独立计数不虚构独立收益

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

11Packed embedding 复制后释放无消费者的引用首版 DiT/runtime · 历史状态：R85 固定＋

怎么做：在 packed copy 完成且没有后续消费者后释放原引用。

为何有收益：减少峰值显存和 allocator 压力，为大业务形状留余量。

精度边界：必须等待 copy 的真实 stream 依赖；不能释放尚被某个消费者读取的 storage。

历史证据：单独速度收益不稳定，主要作为内存治理；不虚构独立降时百分比。

怎样开源：embedding 生命周期；承认主要收益可能为显存

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

12跨 block FC2 residual→下一层 norm/quant首版 DiT/runtime · 历史状态：R85 固定＋

怎么做：以单消费者载体串联相邻 block，8 steps×49 连接共 392 次跨层消费；8 次末层单独收尾。

为何有收益：消除跨层中间激活写读，减少 launch。

精度边界：状态绑定 request/step/block/generation/owner/pointer；不能用上一 step 的值。同实例并发不满足资格，必须隔离或回退。

历史证据：属于当前精确组合收益，尚未单独测整服务贡献。

怎样开源：跨 block 状态最需重构；request 隔离、取消、重入必测

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

13Out-proj/FC2 INT8 GEMM gate-residual epilogue首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：在 epilogue 接上 gate/residual，但显式保留 INT32→FP32 scales→bias→BF16 branch→BF16 gate→FP32 FMA→BF16 的原顺序。

为何有收益：省掉分支结果的额外全量写读和 kernel launch。

精度边界：不能删 BF16 中间舍入或改变 FMA 边界；只作为 owner 元数据保留的 buffer 不得被当成已初始化数据读取。

历史证据：局部链 −4.783%；out-proj＋FC2 完整组合容量 +0.468%。分母不同。

怎样开源：GEMM epilogue 保留原舍入；含源码与数值测试

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

14FC1 与 QKV 的 tile raster 配置首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：FC1 采用 config3/swizzle8，QKV 使用 config5；短 M 和真实长 M 分开验证。

为何有收益：改善 tile 调度与缓存复用；不改变数学运算。

精度边界：尺寸、align、bias、scale 和 epilogue 资格保持；不能按短 microbenchmark 选全业务默认配置。

历史证据：最终累计对照包含该项，未另报独立百分比。

怎样开源：真实 shape 的 FC1/QKV tile 分派，不固化短测结果

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

15QKV projection 后的 RMS/RoPE/Q quant/V partial-max 融合首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：连接投影输出和 RMS/RoPE/Q 量化/V partial-max，按原中间舍入生成后继所需数据。

为何有收益：减少高带宽中间张量、独立统计扫描和 launch。

精度边界：K 中心化依赖与 anchor 定义照旧；Q/K/V 各自 scale 与 padding 照旧。

历史证据：是 R85 累计 −1.905% 组合的一部分，不能再次叠加到最终 A→B。

怎样开源：QKV/RMS/RoPE/quant；保留量化落点与权重身份

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

16当前输入的 9 行 K-only anchor 与 4-warp K fusion首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：每次从当前输入投影 9 行 K-only anchor；使用 4-warp K fusion，省去不被消费的 Q/V。

为何有收益：按真实消费者删除无用工作，减少小路径调度开销。

精度边界：每个 step 重新计算当前 K；不是跨 step cache，也不替换当前 attention 结果。

历史证据：与 QKV/末层裁行整组新增 −1.905%，R126 再现 −1.897%；两者是同一收益的验证。

怎样开源：当前 K-only anchor；不得命名为跨步 cache

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

17末层 reference prefix 无消费者行裁剪首版 DiT/kernel · 历史状态：R85 固定＋

怎么做：根据消费者关系仅计算 live query 与后续 GEMM 行；其他 query 需要的 K/V 仍完整保留。

为何有收益：消除最终输出不依赖的计算，而不减少有效 token、层数或采样次数。

精度边界：原 prefix residual/填充、对齐和形状语义照旧；未知输入关系不能套用。没有稀疏注意力或早停。

历史证据：纳入 R85 新增 −1.905% 组合；未单独分配速度数字。

怎样开源：末层死输出消除；必须证明消费者集合，K/V 保留

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

18INT8 ConvRot ViT3D decoder，保留旧 FP16 encoder第二阶段 VAE/上游集成 · 历史状态：R85 固定＋

怎么做：视频 decode 切换 .35 配套 INT8 ConvRot 权重与新版模型/helper。36 个 ViT3D block 共 144 个量化 Linear；encoder 继续旧类与旧权重。

为何有收益：将 QKV、attention output 和 FFN w1/w2 主要乘法改用量化路径，降低权重带宽与计算成本。

精度边界：量化会改变像素；这项只主张实测差异很小，不能按位无损。模型含 F16/F32 元件；不把历史 FP16 标成 BF16。

历史证据：历史 TRT 阶段 16.559342→9.959952 s，−39.853%；本次原生 FP16 基线的完整收益以新的直接实测为准。

怎样开源：INT8 decoder opt-in；原作者与权重许可清楚标注

归属：上游量化模型与实现，项目接入验证。本仓库尚未迁入对应 GPU 实现。

19VAE 内部 RMS/SwiGLU 输入量化与残差 epilogue第二阶段 VAE/上游集成 · 历史状态：R85 固定＋

怎么做：新版 linear_input_act 把 RMSNorm/SwiGLU 接进 ConvRot 量化；支持的 Linear 使用 residual/residual_scale epilogue，Q/K norm 与 RoPE 融合。

为何有收益：减少 36 层 decoder 内的中间张量和 launch。

精度边界：Kitchen .33 的 8 参数 ABI 变为 .35 的 10 参数，act_weight/act_eps 必须传递；旧 wrapper 只对已验证资格截获。

历史证据：上游 INT8 decoder 的组成部分；没有把它与 INT8 decoder 收益重复相加。

怎样开源：沿用上游输入激活/epilogue/RoPE；ABI 版本核实

归属：上游实现与项目兼容迁移。本仓库尚未迁入对应 GPU 实现。

20Tile 批量、预分配 canvas 与引用释放第二阶段 VAE/上游集成 · 历史状态：R85 固定＋

怎么做：按显存限制使用最多 4 个 tile，输出写预分配 canvas；旧 tile 消费后及时释放，保留原时空 overlap。

为何有收益：限制峰值内存、减少拼接和重复分配，为 decoder 算子留工作空间。

精度边界：不改变 tile 边界、blend 权重、叠加顺序；不能在尚需 blend 的 tile 上提前转 uint8。

历史证据：未单独隔离端到端收益；更大 tile 并未形成默认稳定优化。

怎样开源：tiling/canvas 不变；区分上游能力与接入工作

归属：上游 canvas/tile 能力与项目输出接入。本仓库尚未迁入对应 GPU 实现。

21最终 blend→GPU RGB8 转换融合第二阶段 output/kernel · 历史状态：R85 固定＋

怎么做：仅在原 blend 完成后，GPU 按原 FP32 std/mean、clamp、×255、truncate 顺序产生 RGB8，每通道传 1 byte。

为何有收益：把 D2H 数据量降到四分之一，减少 CPU 转换与主机临时大张量。

精度边界：禁止改变边界结果的 FMA contraction；truncate 不能换 round；未结束的 overlap 区间保持 FP32。

历史证据：这项是精确输出工程；传输字节 −75% 不等于完整耗时 −75%。

怎样开源：最后 blend 后 RGB8；高效输出接口单独设计

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

22双 pinned buffer 与事件驱动 D2H第二阶段 output/runtime · 历史状态：R85 固定＋

怎么做：compute 记录 ready event，copy stream 等待后异步 D2H；CPU 等 copied event 消费，消费完成才归还 slot。双 slot 有明确上限和背压。

为何有收益：把可重叠的搬运隐藏在后续 GPU 工作中，并约束主机内存。

精度边界：record_stream、强引用、GPU 源与 CPU 目标生命周期必须完整；CPU 仍在读时不能复用锁页 slot。

历史证据：历史帧交接包含累计优化，不能全部归因 D2H；本次直接总耗时已包含 R85 输出路径。

怎样开源：双 pinned slot 和事件；消费者归还与取消排空

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

23CPU x264/AAC/MP4 与下一请求 GPU 重叠可选服务示例 · 历史状态：服务层已验证＋

怎么做：请求 N 的 RGB/PCM 进入限量 CPU 编码队列，GPU 可以处理 N+1；mmap/帧缓冲由当前 export 独占。

为何有收益：利用 CPU 与 GPU 的不同资源提升连续队列吞吐。

精度边界：以 MP4、上传和结果提交全部完成作为成功；需排空、取消、失败处理和按总字节背压。GPU 完成不等于请求成功。

历史证据：两臂当时已启用异步 export；这些是历史累计收益。本次单请求 A/B 没有测试跨请求重叠吞吐。

怎样开源：有界 CPU 编码与下个 GPU 请求；不计作单个节点收益

归属：原部署已有异步能力，项目保留并约束所有权。本仓库尚未迁入对应 GPU 实现。

24本地不可变模型缓存与 Qwen 保留热页可选服务示例 · 历史状态：服务层已验证＋

怎么做：将固定模型放本地不可变缓存，核对版本/SHA；Qwen 使用 mark_cold=False 保留活跃页。

为何有收益：以主机内存换取共享盘读量和加载波动降低。

精度边界：每副本需要内存预算，不能无限复制；已缓存文件仍按身份校验；当前 Qwen 未来拆分不算本次收益。

历史证据：当前计时排除首次读权重与 Qwen，所以不能给本项分配这次总加速中的百分比。

怎样开源：本地缓存身份与 RAM 预算；去内部存储和 Qwen 服务耦合

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

25素材预取、请求隔离与编码排空可选服务示例 · 历史状态：服务层已验证＋

怎么做：在当前 GPU 请求期间准备下一请求素材；当前 CPU 编码/上传可继续；每项以版本、请求 owner 与终态关联。

为何有收益：把不占 GPU 的工作放入可重叠区间，提高持续任务下的资源利用。

精度边界：不得按相似 prompt 直接共享 condition；冻结 condition 只是实验控制变量。失败和取消必须回收对应任务资源。

历史证据：依部署接入而定；本次固定 condition→MP4 比较不覆盖下载/上传和真实 condition。

怎样开源：素材预取/终态/隔离；只保留通用抽象与可运行本地示例

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

26音频 VAE 搬 CPU 的实验与保留 GPU 的原因只公开负结果 · 历史状态：未采用＋

怎么做：曾试 4 线程 CPU 以便与 GPU 视频 VAE 并行；耗时 4.49–9.44 s，PCM 也不同，因此当前继续 GPU FP32。

为何有收益：并行只有在关键路径缩短时才有收益；当前音频在总周期中太短。

精度边界：音频权重 917 个 FP32 tensor；不通过隐式半精度改变 PCM。与视频量化比较时使用同一 PCM。

历史证据：即使完全隐藏当前 GPU audio，完整周期理论可省约 0.05%；没有实测并行净收益。

怎样开源：CPU audio 更慢且 PCM 不同；默认继续 GPU FP32

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

27VAE 阶段静态 cast/load候选研究 · 历史状态：后续候选＋

怎么做：在 VAE 阶段预先按原 dtype/scale cast/load，阶段结束再释放；不是永久同时驻留整个 DiT 与 VAE。

为何有收益：减少动态包装和重复权重处理。

精度边界：必须验证组件切换、下一请求峰值显存和长期生命周期；候选没有并入本次冻结 R85。

历史证据：仅静态完整周期约 −0.20%；静态＋R207 全15视频 −6.802%，分母为 R85 动态 VAE。

怎样开源：静态 VAE 未入 R85；别加进首版已证实收益

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

28R234v2：VAE RMS/RoPE→Q 旋转量化候选研究 · 历史状态：后续候选＋

怎么做：CTA 内处理 32 token，Q 写 shared 后按原 32-row/8 组 scale 旋转量化；K 保留原 FP16 写回和 anchor 检测。

为何有收益：缩短 VAE attention 输入准备，减少 Q 中间往返。

精度边界：首版 FMA/倒数边界不一致被拒绝；仅 v2 保留原数值。hook 只在 VAE D64 作用域使用并可靠恢复。

历史证据：与 R244 组合视频 −0.632%，相对静态＋R207；不能再与 R85 总收益相加。

怎样开源：VAE Q 融合 v2，可独立跟进；不覆盖 DiT D128

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

29R244：VAE D64 cached-Q 与小 Q tile候选研究 · 历史状态：后续候选＋

怎么做：Q 保留寄存器，CTA_Q 128→64、WARP_Q 32→16，K tile=64；约 128 register、4 CTA/SM。

为何有收益：提升该短序列 D64 shape 的并发 CTA 与 Tensor 管线活动。

精度边界：原 128-row 量化 scale 索引、softmax/PV 顺序保留；不能拿 VAE D64 核覆盖 DiT D128。

历史证据：局部 attention 约 −11%，全视频组合仅 −0.632%；完整 VAE <5s 未达到。

怎样开源：VAE D64 cached Q；微观收益与全视频收益分开

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。

30新 PyTorch/Triton、NVFP4 与近似计算候选只公开实验说明 · 历史状态：未采用＋

怎么做：Torch 2.14/Triton 3.8 完整 INT8 对照未获得稳定 DiT 提速且轨迹改变；CPU audio、NVFP4、近似跳算等没有进入当前无损算子基线。

为何有收益：保留负结果，避免复用时把试验开关误当推荐配置。

精度边界：新栈并未重编全部自定义 CUDA 核；不能据此排除未来编译收益。NVFP4 不按位等价；近似方案须另做视频/音频评估。

历史证据：当前没有可纳入默认 R85 的新增收益。详细负结果与 LoRA 质量见原章节。

怎样开源：新栈/NVFP4/cache 等不入默认；性能与精度另验

归属：项目适配与优化。本仓库尚未迁入对应 GPU 实现。
